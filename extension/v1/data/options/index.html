WS/TCP bridge

The external server must speak the ws → TCP/TLS bridge protocol. Read FAQs page for a sample server. In this mode, the extension does not require native client to operate.

Master password

Optional. When set, saved account passwords are stored encrypted with it; leave empty to store them in plain text. Setting, changing or removing it re-encrypts saved passwords automatically. The password itself is kept in session storage only, so it is asked for once per browser session.

Debugging

Bridge debug applies when the built-in bridge (re)starts; in external mode the external server does its own logging.

Email list

Maximum number of emails shown in the message list before paging applies to every account. Prev/next controls appear in the list when there are more emails.

When on, starred conversations are grouped above unstarred ones; the selected sort order applies within each group.

The extension keeps a local copy of your mail (folders, lists and message bodies) and syncs it with the server periodically and on every action. "All" stores every message body for instant offline reading; the older-window options only fetch the newest N bodies per folder, everything else is pulled on demand when you open an email.

Badge counter

The service worker asks every badge-enabled account for unread mail on this interval. The badge shows the combined unread total when it is not zero, and its title lists each account's count. Accounts without a usable password in this browser session are reported there but skipped.

With the return-from-idle check on, the badge also runs one silent check whenever the machine becomes active again (wake, unlock or resume), so the count is fresh the moment you are back.

The age limit restricts the badge to unread mail newer than the chosen window; older unread mail no longer counts. It applies to the folder mode and to search-query mode alike. When the IMAP core build lacks search support, the coarse folder fallback count cannot be age-filtered and ignores the limit.

Preferences backup

Export downloads every setting stored by the extension — accounts, filters, UI preferences and action overrides — as a JSON file. Import restores such a file; you are asked whether to merge it with the current settings or replace everything. Account passwords are included only when a master password encrypts them, or when you explicitly agree to export them in plain text. Importing an export that used a different master password leaves its passwords unreadable until re-entered.

When an override is enabled, the button first copies every selected email as a raw .eml file (named date-uid.eml) into the destination directory — existing files are never overwritten. Only then the server is touched: with "Delete from IMAP" checked the copied emails are deleted from the mailbox; without it a dialog asks whether to mark them \Deleted, move them to the server's normal spam/archive/trash folder, or leave them untouched. Scheduling

Filters run in the extension's background worker: before every badge update and whenever the mail client opens. Each enabled filter is applied to new messages in INBOX, first match wins. When the first filter for an account is saved you are asked whether to process its existing unread mail.

"All unread" applies the filters to every unread message currently in INBOX — including older mail that arrived before the filters existed — without changing what the automatic runs consider new. "New" processes only the messages that arrived after the previous run. The choice affects this manual run only; the automatic runs (before every badge update and on client open) always filter new mail.

Edit Filter
Rule

Fields: subject: from: (or sender:) to: body: — each applies to the word or "quoted phrase" after it. A bare word matches anywhere (subject, sender, to and body). Combine terms with and, or, not and parentheses; and is implied between adjacent terms. Matching is case-insensitive "contains". Each line is a separate rule: a message is acted on when it matches any one line (lines act as OR).

Examples: subject:"MyB :: " and not "IP Blocking" — subject contains "MyB :: " but not "IP Blocking"; (from: "DDD" or from: "FFF") and (to:"mdrov@gmail.com" or to:"qe@gmail.com"). With one rule per line, a second line like from:"newsletter@example.com" filters that sender too — either line matching is enough. An empty query matches every new message.
